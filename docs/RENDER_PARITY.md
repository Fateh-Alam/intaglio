# Render Parity Contract

Preview, A/B, proof, export, batch, and thumbnails compile the same canonical graph. The order is decode/orient, global geometry, a single linear-sRGB input transform (skipped for 16-bit linear RAW sources), ordered plates and mask expressions, global film/optical/bloom/halation/sharpen, sRGB display transform, then text/watermark in output coordinates. Tone curves and creative LUTs operate on display-encoded values inside the linear pipeline (encode, apply, decode) with extended range above 1.0.

At equal dimensions, each fixture must independently satisfy:

- PNG versus lossless preview readback: SSIM >= `0.9995`, mean CIEDE2000 <= `0.25`, p99 CIEDE2000 <= `0.75`.
- JPEG/WebP quality >= 90 versus pre-encode reference: SSIM >= `0.995`, mean CIEDE2000 <= `1.0`.
- Crop corners, mask boundaries, text baselines, and watermark anchors: <= `0.5` output pixel.
- Tile-edge regions use the same ordinary-image thresholds.

The automated equal-size fixture uses an actual WebGL preview readback and separately rendered/decoded PNG, JPEG, and WebP exports. Output encoding uses pinned jSquash browser WASM codecs: Rust PNG, MozJPEG, and libwebp. For the beta's quality-90-or-higher contract, MozJPEG uses maximum-quality 4:4:4 chroma and WebP uses lossless mode; this intentionally favors the perceptual gate over file size. File signatures and the published lossless/lossy thresholds are checked in both engines.

The fixture enables geometry, LUT/domain handling, an adjustment plate, radial, linear, luminance, color-range, and brush masks, text, watermark, and deterministic grain. A forced 2-by-2 tile version exercises global UV mapping, overlap, crop, stitch, masks, grain, and overlays against the non-tiled reference. Both fixtures pass independently in Playwright Chromium and WebKit. Cached transparent overlay layers remove WebKit's otherwise context-dependent glyph-edge rasterization while keeping visible preview and export content on the same compositor.

Remaining fixture qualification covers the full neutral/gradient/high-dynamic-range/skin/saturated image matrix, each mask operator in isolation, bloom/halation, a 100-megapixel tiled stress run, overlay landmark extraction, cross-browser byte/perceptual comparison, and actual Safari. Playwright WebKit is local automated evidence; it is not real Safari or installed-PWA evidence.

Parity cannot detect an operation that is equally wrong in preview and export, so the probe also runs correctness gates against known results: a full-coverage neutral plate must be a no-op, a 17-point identity LUT must be a no-op (mean CIEDE2000 <= `0.25`), and an inverting master curve must reach the exported PNG (mean CIEDE2000 >= `20`).

## Native engine (Mac app)

The Mac app's native engine, `crates/etch-core` (WGSL on wgpu, Metal on macOS), must reproduce the web renderer. `tests/browser/native-parity.spec.ts` renders the shared cases in `app/native-parity/cases.json` on the fixture `public/parity/native-fixture.png` twice: with the web export pipeline at `/native-parity` (Chromium and WebKit), and with `etch-core` (`cargo run --example parity_cases`). It needs a Rust toolchain and a GPU, and skips without them. On macOS the Chromium comparison uses ANGLE Metal. The ordinary web render-contract tests still use the default browser backends.

WebGL stores half-float intermediate values. Etch uses f32 arithmetic and stores half-float working images between passes. They can round a channel one 8-bit step apart, and one step in one channel costs up to about 1 CIEDE2000 even on mid-grey (0.97 measured at rgb 128,128,128). An 8-bit channel cap is the wrong yardstick: on a near-black with a faint tint, OKLab hue is barely defined, so a mixer band edge can flip a channel by 7/255 there, yet that pixel measures ΔE 1.45, less visible than a 1/255 step on a mid-tone (ΔE 1.81 in the tint case). So the cross-engine bar is perceptual, per case: **every pixel** that differs by more than one 8-bit step has CIEDE2000 <= `2.0` (one step is the rounding floor, and on some dark saturated colours it alone measures ΔE 2.2), mean <= `0.25`, p99 <= `1.5`, SSIM >= `0.9995`. Cases that resample the photo (straighten, zoom, lens, keystone, anamorphic) allow ΔE `5` per pixel: the fixture's synthetic bands change ~220 levels within one texel, so a 1/20-texel difference in sample position moves that one pixel ~11 levels; their mean, p99 and SSIM bars are unchanged. God light shares that bar: its specular term raises a normal built from neighbour taps to the 32nd power, so the same sub-texel difference beside a hard edge is amplified ~32× (one pixel at ΔE 2.06 in Chromium; WebKit agrees with the native engine within 1/255). Where a resampled photo ends, a pixel can be inside for one renderer and outside for the other (Chromium and WebKit disagree there too); those are counted separately and must stay within a one-pixel outline.

Geometry parity needed two web fixes (2026-11-25). Photo textures are now marked sRGB, so the GPU decodes before filtering and rotation, lens correction, keystone and mipmapped previews blend in linear light; blending encoded values had darkened hard edges by up to ΔE 23. And the geometry pass now samples outside its in-photo test: inside the `if`, pixels on the photo's edge had no valid neighbours for mip selection, and WebKit drew a smear of the photo's average colour along straightened edges. Same-engine comparisons keep the stricter thresholds above.

Measured 2026-11-25 for every base develop control, tone curves (including an inverting curve), the eight-band color mixer, skin protection, three-way grading, creative LUTs, crop, straighten, lens distortion, keystone, anamorphic, adjustment layers with every mask kind (radial, linear, luminance, colour range, legacy kinds, brush; add/subtract/intersect; layer opacity; on a cropped photo) and combined edits, in both Chromium and WebKit: every pixel within 1/255 except a handful at 2/255 and one resampled hard-edge pixel at ΔE 3.96 (Chromium); mean CIEDE2000 <= 0.17, SSIM >= 0.99995.

Global passes, measured the same day: all 31 film looks plus a part-strength look, halation, bloom, vignette, chromatic aberration, anamorphic streaks, god light, grain, film border, sharpening (both signs), structure, and a stack of all of them over a local layer on a cropped photo. In both browsers every pixel is within 1/255, except god light's one amplified pixel above; mean CIEDE2000 <= 0.18. Porting them found two web bugs, both now fixed in the shared shader sources:

- **Grain differed by browser.** The grain hash was `fract(sin(x) * 43758.5)`, whose large-argument `sin` isn't the same on every GPU driver: WebKit's grain matched Metal's, and Chromium's didn't (up to 115/255 on one pixel). So a document's grain changed with the browser. Both engines now use the same integer PCG hash per output pixel, which is exact everywhere.
- **Film looks could black out the photo.** Looks use `pow()` and HSL, and a channel pushed below zero (a strongly saturated local layer, say) became NaN. On its own, a NaN pixel is one black dot, but halation and bloom blur it across the frame: the `global-stack` case rendered entirely black in WebKit and in the native engine (Chromium happened to produce no NaN there). Film looks now take non-negative input, and HSL saturation is bounded where its denominator reaches zero.

The SDR display pass converts linear color to sRGB. Live preview and export use the same triangular dither at the output pixel, including tiled web exports. Creative Effects receives the undithered encoded image to keep tone thresholds and palette quantization stable. It preserves source alpha. To regenerate the native effects from the web catalog, run `node scripts/gen-creative-wgsl.mjs` with Cargo available. Glyph cases supply the same canvas mask to both renderers. Dither and pixel sort read a bounded logical grid into Rust, then upload only the resulting effect texture.

The 105 cross-engine cases pass on Apple M3 in Chromium with ANGLE Metal and in Playwright WebKit. All 11 Creative Effects cases and both RGB16 cases differ by at most one 8-bit step per channel. The native GPU suite also renders the entire 136-effect catalog and checks that every effect preserves source transparency. Chromium's SwiftShader path (`ETCH_PARITY_SOFTWARE=1`) still exceeds the pixel tolerance for Halftone, Chrome and the cropped effect stack. Its ordered dither, error diffusion and pixel sort fixtures match the native result byte for byte.

Each further pass ported to `etch-core` adds its cases to the same file, and every case except the neutral one must visibly change the photo, so a step that silently does nothing in both engines can't pass.

The native viewport suite checks source-pixel zoom beyond the default GPU texture limit, pans between two resident source tiles, compares tiled and full-frame spatial effects, and verifies that a selected mask tint stays aligned at zoom and leaves export pixels unchanged. The preview compositor keeps mask coverage separate from the image data used for exports and whole-photo scopes.

The comparison tests check the original within an edited crop, a snapshot divider at a panned 1:1 view, and clipping warnings confined to the edited side. A whole-photo readback captures the edited crop even when the viewport shows Before. The Versions workflow is also exercised in Chromium and WebKit with snapshot capture, a subsequent edit, and both sides of the split sampled from the framebuffer.

Two parity cases feed the same decoded linear RGB16 fixture to the web and Metal pipelines before and after an exposure lift. The native tests also check shadow detail below the 8-bit preview's quantization floor and pan through an RGB16 image that exceeds the GPU texture limit. The desktop IPC test verifies that chunked uploads preserve every source code and reject gaps before publishing the photo.

Saved serial grades are qualified with Film before and after Develop, scalar overrides, a disabled node, partial plate-stack opacity, and a reordered sequence of LUT, halation, bloom, optical, and sharpen passes. Reversing Film and Develop must visibly change the result. Native preview, scopes, and snapshots read the same ordered graph. The canonical graph keeps its fused shader, and eligible reordered color stages run together in their saved order while retaining the half-float boundaries.

Color-managed fixtures carry the macOS Display P3 and Adobe RGB (1998) profiles. The editor converts an imported RGB profile to its existing SDR sRGB working space. The original still carries its embedded profile. Native import uses relative colorimetric conversion and WebGL receives browser-converted sRGB codes before upload. The import cases require an absolute channel error of at most two codes, or three after the test grade, and keep the same mean, p99 and SSIM limits. Independent conversions can round differently in the shadows even when the resulting image meets those limits.

Bloom and halation measure blur against the unscaled cropped photo. Film grain uses the same photo-space cells at every scale and averages them where the viewport has less detail. `crates/etch-core/tests/post.rs` and the browser render contract compare half-size grain and half- and quarter-size glow against a reduced full-size render. The browser test also forces overlapping tiles for each of the three effects. In Safari 27.3 the largest mean channel error was 1.86 out of 255 across the scale fixtures, with 0.89 for grain. The tiled glow and grain cases all stayed below 0.02 mean CIEDE2000.

The spec also checks a correctness rule directly in the web renderer: the color mixer's luminance bands leave pure greys untouched. OKLab returns rounding noise as the "hue" of a grey, so before 2026-11-25 a luminance band could brighten or darken neutral pixels at random, and differently per GPU. Bands now fade in with chroma, reaching full strength at OKLab C = 0.02.

Inside the crate, `cargo test` also checks each WGSL pass against its CPU twin (`reference.rs`) within 1/255, and that default settings leave a photo untouched.
